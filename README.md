# AutoReel: ادیت خودکار ریلز اینستاگرام

ویدیوی خام عمودی رو آپلود می‌کنی، متنش رو تأیید می‌کنی و ریلز ادیت‌شده تحویل می‌گیری. ادیت شامل این‌هاست:
- حذف مکث‌ها
- زوم خودکار روی صورت
- زیرنویس فارسی کلمه‌به‌کلمه
- موشن‌گرافیک
- افکت صوتی و موسیقی

```
پنل (Next.js) ──► API (Node.js/Fastify) ──► PostgreSQL (داده‌ها + صف کارها با pg-boss)
                                              ▲
                       ورکر (Node.js) ─────────┘──► موتور ادیت (Python: autoedit) ──► storage/
```

| بخش | مسیر | کار |
|---|---|---|
| پنل | `apps/web` | آپلود، تأیید متن، وضعیت، پخش و دانلود، تنظیمات سبک پیج |
| API | `apps/api` | ورود، ویدیوها، متن، نسخه‌ها، فایل‌ها |
| ورکر | `apps/worker` | سه کار: تحلیل ← کارگردانی ← رندر |
| کارگردان | `packages/director` | نوشتن نقشه‌ی ادیت. فعلاً قاعده‌محوره و کلید API نمی‌خواد. Claude در مرحله ۳ وصل می‌شه. |
| دیتابیس | `packages/db` | جدول‌ها و migrationها (Drizzle) |
| موتور | `packages/engine` | تحلیل، اعتبارسنجی و رندر ویدیو (پایتون). راهنمای خودش: `ENGINE.md` |

## اجرا روی ویندوز

**پیش‌نیازها:**
- Docker Desktop (با WSL2). در تنظیمات Docker Desktop بخش Resources، حداقل ۶ گیگ رم و هرچقدر هسته‌ی CPU که می‌تونی بهش بده.
- Node.js 22 و Git (فقط برای حالت توسعه لازمن).

```powershell
git clone https://github.com/shenskho/instagram.git
cd instagram
copy .env.example .env      # ایمیل، رمز و JWT_SECRET رو عوض کن
```

### حالت ۱: اجرای کامل با یک دستور
```powershell
docker compose up --build
```
بعد پنل رو در مرورگر باز کن: http://localhost:3000

اولین ساخت چند دقیقه طول می‌کشه، چون مدل‌ها و فونت‌ها (حدود ۲۶۰ مگابایت) دانلود می‌شن.

### حالت ۲: توسعه (تغییر کد بلافاصله اعمال می‌شه)
```powershell
npm install
docker compose up -d db worker     # دیتابیس و ورکر (پایتون و ffmpeg) داخل Docker
npm run dev                        # API روی 4000 و پنل روی 3000، روی خود ویندوز
```
اگه کد ورکر یا موتور رو تغییر دادی: `docker compose up -d --build worker`

### استفاده
1. وارد شو. ایمیل و رمز همونیه که در `.env` نوشتی.
2. یک یا چند ویدیوی خام رو در قاب سمت راست رها کن.
   - چند ویدیو به ترتیب فهرست به هم چسبونده می‌شن. ترتیب رو با فلش‌ها عوض کن. ویدیوی افقی روی نسخه‌ی تارِ خودش قرار می‌گیره.
   - اگه بخوای، «زاویه‌ی دید» ویدیو رو هم بنویس: ویدیو قراره بیننده رو به چی برسونه.
3. بعد از تحلیل (حدود ۳۰ تا ۶۰ ثانیه)، صفحه‌ی بررسی باز می‌شه:
   - **متن:** هر کلمه‌ای که اشتباه شنیده شده رو درست کن.
   - **ویدیوی بدون حرف:** اگه کسی حرف نزنه، یک توضیح کوتاه بنویس. جمله‌هاش به‌ترتیب روی تصویر نمایش داده می‌شن.
   - **گزینه‌ها:** نشانگر رو روی هر گرافیک، موشن یا ادیت نگه دار تا پیش‌نمایشش رو ببینی. هر چندتا که بخوای انتخاب کن. همه‌ی انتخاب‌ها در ریلز میان و کارگردان هم هر جا لازم بدونه چیزهای دیگه اضافه می‌کنه.
   - در آخر «تأیید و شروع ادیت» رو بزن.
4. وقتی رندر تموم شد، ویدیو رو پخش یا دانلود کن.
   - بخش «در این ریلز» نشون می‌ده هر گزینه کجای ویدیو اومده. با زدن روی هر زمان، ویدیو از همون لحظه پخش می‌شه.
   - برگه‌ی بازبینی همه‌ی لحظه‌های گرافیکی رو یک‌جا نشون می‌ده.
   - با «ساخت نسخه‌ی جدید» گزینه‌ها یا زاویه‌ی دید رو عوض کن و یک نسخه‌ی دیگه بساز.
5. قانون‌های کلی پیج رو در صفحه‌ی «سبک پیج» تنظیم کن: قلاب، سؤال آخر، تعداد گرافیک‌ها، موسیقی و…

### پیش‌نمایش گزینه‌ها
پیش‌نمایش‌ها در `apps/web/public/previews` هستن و خود موتور ادیت اون‌ها رو از ویدیوی تست ۲ ساخته. برای ساختن دوباره از یک ویدیوی دیگه، بازه‌های زمانی بالای فایل `packages/director/src/previews.ts` رو برای اون ویدیو عوض کن و اجرا کن:
```bash
npx tsx packages/director/src/previews.ts analysis.json segments.json --source sample.mp4 --out apps/web/public/previews [--fix fix.json] [--only stamp,jungle]
```

فایل‌ها در پوشه‌ی `storage/videos/<id>/` ذخیره می‌شن: ویدیوی خام، تحلیل، نقشه‌ها و خروجی‌ها.

## تنظیمات (`.env`)
| متغیر | توضیح |
|---|---|
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | حساب ورود. اولین بار که API بالا میاد ساخته می‌شه. |
| `JWT_SECRET` | یک رشته‌ی طولانی و تصادفی |
| `STT` | `local` = Whisper محلی (برای فارسی ضعیفه). مرحله ۲: `elevenlabs` |
| `DIRECTOR` | `rule` = کارگردان قاعده‌محور. مرحله ۳: `claude` به‌همراه `ANTHROPIC_API_KEY` |
| `RENDER_WORKERS` | تعداد پردازه‌های موازی رندر. حدوداً تعداد هسته‌ها منهای ۱. |
| `MAX_VIDEO_SECONDS` | حداکثر طول ویدیوی ورودی (بعد از چسبوندن) |
| `MAX_CLIPS` | حداکثر تعداد ویدیو در یک آپلود (پیش‌فرض ۱۰) |

## مشکلات رایج
- **پورت 3000، 4000 یا 5432 اشغاله:** برنامه‌ای که از اون پورت استفاده می‌کنه رو ببند، یا شماره‌ی پورت رو در `docker-compose.yml` عوض کن.
- **رندر کنده:** هسته و رم بیشتری به Docker Desktop بده و `RENDER_WORKERS` رو بالاتر ببر.
- **شروع از صفر (پاک شدن دیتابیس):**
  ```powershell
  docker compose down -v
  ```
  بعد پوشه‌ی `storage/videos` رو هم پاک کن.
